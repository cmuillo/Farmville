🏭 Factory Method

La funcion create_entity(definition) actua como fabrica: elige la subclase correcta segun la categoria, sin que el motor necesite saber que clase usa.

# Clase base define la interfaz
class FarmEntity:
    def required_cure(self) -> Optional[str]:
        return None  # default: sin cura

# Subclases sobreescriben el metodo (polimorfismo)
class PlantEntity(FarmEntity):
    def required_cure(self): return "pesticida"

class AnimalEntity(FarmEntity):
    def required_cure(self): return "medicina"

class DecorativeEntity(FarmEntity):
    pass  # hereda None = sin cura

# Factory: una sola funcion decide la clase
def create_entity(definition):
    if definition.category == "plantacion": return PlantEntity(definition)
    if definition.category == "animal":     return AnimalEntity(definition)
    if definition.category == "arbol":      return TreeEntity(definition)
    return DecorativeEntity(definition)

# Uso polimorfico: motor no sabe que clase tiene
entity = create_entity(definition)  # Factory
cure   = entity.required_cure()      # Polimorfismo
Pregunta de examen: "Donde esta el polimorfismo?" → en required_cure(): la misma llamada produce resultados distintos segun la subclase concreta, sin un if/else en el motor.

🗺 GameState

Estado raiz que contiene todo. Se guarda/carga completo.

  • coins — monedas actuales
  • terrains — lista de Terrain
  • items — dict id→PlacedItem
  • inventory — dict key→cantidad
  • statistics — Statistics
  • GameState.new(name) — crea inicial
@dataclass  # genera __init__, __repr__, __eq__ automaticamente
class PlacedItem:
    item_id: str
    remaining_seconds: int = 0
    ready: bool = False
    condition: Optional[str] = None   # None | "plaga" | "enfermedad"
    dead: bool = False

    def to_dict(self) -> dict:
        return {"item_id": self.item_id, "remaining_seconds": self.remaining_seconds, ...}

    @classmethod
    def from_dict(cls, data: dict) -> "PlacedItem":
        return cls(item_id=data["item_id"], remaining_seconds=data.get("remaining_seconds", 0), ...)

def save_game(state: GameState) -> None:
    # mkdir crea la carpeta "data/" si no existe
    SAVE_FILE.parent.mkdir(parents=True, exist_ok=True)
    with SAVE_FILE.open("w", encoding="utf-8") as fp:
        json.dump(state.to_dict(), fp, ensure_ascii=False, indent=2)

def load_game() -> Optional[GameState]:
    if not SAVE_FILE.exists():
        return None  # sin archivo → None
    with SAVE_FILE.open("r", encoding="utf-8") as fp:
        data = json.load(fp)
    return GameState.from_dict(data)

def delete_save() -> None:
    if SAVE_FILE.exists():
        SAVE_FILE.unlink()  # elimina el archivo
Patron to_dict / from_dict: cada clase sabe como convertirse a dict (para JSON) y como reconstruirse desde dict (al cargar).
★ Tema de Examen
Concurrencia con threading
ProductionThread — un hilo por cada item productivo activo
🔀 ProductionThread
  • daemon=True → muere cuando cierra el programa
  • stop_event (threading.Event) → senal de parada cooperativa
  • run() → bucle: sleep(1) → tick_item()
  • stop() → llama stop_event.set()
🔒 RLock — seguridad de hilos

El motor usa threading.RLock() para proteger el estado compartido.

  • Lock normal: bloquea incluso para el mismo hilo
  • RLock (reentrant): el mismo hilo puede adquirirlo varias veces sin bloquearse
Condicion de carrera: sin lock, dos hilos podrian leer y modificar state.coins al mismo tiempo → resultado incorrecto. 
class ProductionThread(threading.Thread):
    def __init__(self, engine, item_id):
        super().__init__(daemon=True)  # muere con el programa
        self.engine = engine
        self.item_id = item_id
        self.stop_event = threading.Event()

    def run(self):
        while not self.stop_event.is_set() and self.engine.running:
            time.sleep(1)               # tick cada 1 segundo
            if self.stop_event.is_set(): break
            self.engine.tick_item(self.item_id)

    def stop(self):
        self.stop_event.set()  # senal de parada (no fuerza)

# En el motor, cada write esta protegido:
def tick_item(self, item_id):
    with self.lock:              # adquiere el RLock
        item = self.state.items.get(item_id)
        ...                      # modifica estado de forma segura
★ Mas complejo del proyecto
Maquina de Estados: tick_item()
Llamado cada segundo por cada hilo — gobierna todo el ciclo de vida
🔄 Produciendo remaining_seconds – 1 por tick.
0.3% chance de contraer condicion.
🦠 Con condicion condition_remaining – 1 por tick.
Si llega a 0 → muere.
✅ Listo ready = True.
Si auto_harvest → cosecha.
Si no → gracia 90s.
💀 Muerto dead = True.
Hilo ignora el item.
Se puede limpiar. 
def tick_item(self, item_id):
    with self.lock:
        item = self.state.items.get(item_id)
        if not item or item.dead: return               # guard

        # 1) Tiene plaga/enfermedad?
        if item.condition:
            item.condition_remaining -= 1
            if item.condition_remaining <= 0: item.dead = True
            return

        # 2) Ocurre plaga este tick? (0.3% de probabilidad)
        if random.random() < 0.003:
            item.condition = "plaga"; item.condition_remaining = 90; return

        # 3) Conteo normal de produccion
        if definition.is_productive and not item.ready:
            item.remaining_seconds -= 1
            if item.remaining_seconds <= 0: item.ready = True; return

        # 4) Listo → cosechar o contar gracia
        if item.ready and self.state.auto_harvest:
            self.harvest(item, automatic=True)
        elif item.ready:
            item.ready_wait_seconds += 1
            if item.ready_wait_seconds >= 90:  # se perdio
                item.ready = False; item.remaining_seconds = definition.production_time

# after() — bucle de UI sin bloquear la ventana
def _ui_loop(self):
    self.state.statistics.total_play_seconds += 1
    self.refresh_ui()                   # actualiza widgets
    if self.state.statistics.total_play_seconds % 30 == 0:
        save_game(self.state)             # autoguardado 30s
    if self.engine.running:
        self.after(1000, self._ui_loop)  # reprograma
# on_cell_click — manejo de estado pendiente

Regla de Tkinter: todos los widgets deben crearse y modificarse desde el hilo principal. Los ProductionThreads solo modifican el GameState (datos); la UI los lee en el siguiente tick de _ui_loop.
Repaso Final
Preguntas Tipicas de Examen
Respuestas directas a lo que mas se pregunta
❓ POO
  • Donde esta el polimorfismo?
    En required_cure(): misma llamada, distinto resultado segun subclase.
  • Que es el Factory Method?
    create_entity(): centraliza la creacion; el motor no usa if/else para saber que clase crear.
  • Por que separar GameEngine de la UI?
    Logica independiente de la interfaz: mas facil probar, mantener y cambiar la vista.
❓ Hilos y concurrencia
  • Por que se usa lock?
    Evita condiciones de carrera: dos hilos no pueden modificar el estado simultaneamente.
  • Que es daemon=True?
    El hilo muere automaticamente cuando el proceso principal termina.
  • Por que after() en vez de sleep()?
    sleep() congela la ventana; after() programa sin bloquear el hilo de Tkinter.
❓ Persistencia y estructura
  • Que datos se guardan?
    Todo el GameState: jugador, monedas, terrenos, items, inventario, estadisticas, bitacora.
  • Como funciona la serializacion?
    Cada clase tiene to_dict() para guardar y from_dict() para reconstruirse.
  • Donde esta el autoguardado?
    En _ui_loop(): cada 30 ticks llama save_game().
